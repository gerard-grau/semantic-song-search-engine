● 1. What's loaded at backend startup                                                         
                                                                                                
  Entry point: app/backend/api/main.py — lifespan() runs once before FastAPI starts accepting   
  requests.                                                                                     
                                                                                                
  Step A — Embedding model preload (encoder.load_encoder)                                       
  - Downloads/loads intfloat/multilingual-e5-small (HuggingFace transformers — tokenizer +      
  model, ~120 MB) onto CPU or CUDA.                                                             
  - The model is cached in module-level globals (_tokenizer, _model, _device) for the whole   
  process.                                                                                      
  - ~60–90 s on first run from disk; instant on subsequent runs (HF cache).                     
                                                                           
  Step B — Cercador index build (cercador_index.prewarm → CercadorIndex.build)                  
                                                                                                
  1. Songs (data_loader.load_all_songs()):                                                      
    - Reads only the id_lyrics column from embedded_songs.parquet (5 GB file, but just one      
  column → fast). That gives the canonical set of song IDs we have full data for (~78 K).       
    - Streams augmented_songs.csv (latin-1, ~120 MB) row-by-row with the stdlib csv reader    
  (skips malformed rows — ~13 K were malformed last run).                                       
    - Streams cancons.csv (utf-8, ~90 MB) for data, viasona_link, durada.                     
    - Merges the two on id_lyrics → list of ~85 K song dicts (title, artist, album, lyrics,     
  viasona_link, year, duration). No embeddings are loaded here — only metadata.                 
  2. Grups (_load_grups): pandas reads grups.csv → 7 597 groups (id, name, song_count,          
  viasona_link, foto, municipi, regio).                                                         
  3. Noticies (_load_noticies): pandas reads noticies.csv → 4 653 articles (id, title, subtitol,
   snippet, date, viasona_link).                                                                
  4. Parser2 catalog:                                                                         
    - Every song's title + artist, every grup name, every noticia title is fed into             
  Parser2.load_catalog. Parser2 deduplicates and stores them in self.titles / self.artists, plus
   length-bucket maps (_titles_by_len, _artists_by_len) and a 2-gram index over accent-folded
  catalog tokens (_cat_2gram) for fast fuzzy lookup.                                            
    - Result: 60 941 unique titles, 7 521 artists, 35 081 unique tokens.                      
  5. Parser2 lexicon (load_lexicon): pulls top Catalan words from wordfreq (zipf ≥ 2.4) → 50    
  594-word frequency dictionary + 2-gram index.                                                 
  6. Inverted indices in cercador_index:                                                        
    - songs_idx, grups_idx, noticies_idx: token → [(item_idx, field_weight)]. Tokens come from  
  the normalized title/artist/name/snippet of each item; stopwords are dropped at index time.   
  Field weights: title 1.6, artist 1.3, name 1.6, lyrics/snippet 0.4.
    - Phrase maps: songs_title_phrase, songs_artist_phrase, grups_phrase, noticies_phrase       
  (normalized phrase → [indices]) for exact-match boosts.                                       
    - Per-index normalized phrase lists (_songs_title_norm, etc.) for the phrase-edit-distance
  rerank step.                                                                                  
                                                                                              
  Total cold-start cost: ~30 s for the index build (on top of the 60–90 s model preload).       
                                                                                              
  What is NOT loaded at startup:                                                                
  - The embedded_songs.parquet matrix itself (5 GB). Embeddings are streamed lazily per-request
  via data_loader.load_embeddings_for_ids, with a per-ID cache.                                 
  - embedded_songs_2d.parquet is read on first /api/songs request, not at startup (cached     
  after).
